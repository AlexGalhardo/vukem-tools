# Changelog rules

- Keep a Changelog 1.1.0, SemVer tags `vX.Y.Z`, generated by git-cliff (`cliff.toml`) from
  Conventional Commits: every entry links its commit. Do not edit `CHANGELOG.md` by hand; write a
  good commit message instead (`feat` to Added, `fix` to Fixed, `refactor`/`perf` to Changed;
  `docs`/`test`/`ci`/`build`/`chore` are left out).
- Releasing: `git cliff --tag vX.Y.Z -o CHANGELOG.md`, commit `chore(release): vX.Y.Z`, annotated
  tag `vX.Y.Z`, push the commit and the tag; `release.yml` builds the GHCR image and publishes the
  GitHub release with that section.
- Push version tags one at a time. GitHub creates no push event when more than three tags go up in
  a single push, so `release.yml` never runs for them. For a tag already pushed without a release,
  publish it with `gh release create vX.Y.Z --verify-tag --notes-file <section>`, or re-run
  `release.yml` with `workflow_dispatch`.
- Never move a pushed tag.

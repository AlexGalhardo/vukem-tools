## High

### H1. The engine sandbox gives no network, against the documented rule

- Where: `internal/engine/sandbox_linux.go:163` (`isolate` only sets `Setpgid`; limits come from
  `prlimit`), `.claude/rules/engines.md` ("No network for conversion subprocesses"),
  `docs/brainstorming.md:410` ("the sandbox gives no network").
- Problem: only ffmpeg is hardened (`-protocol_whitelist file`, `internal/ffmpeg/ffmpeg.go:69`).
  libvips (SVG and other loaders), Ghostscript, LibreOffice and OCRmyPDF run with the container's
  full network, so a crafted upload can make them fetch internal URLs or the platform metadata
  service (SSRF through the engine), and nothing stops them exfiltrating the file they were given.
- Proposal: run each non-downloader engine in a new network namespace (`unshare --net` via the
  runner when the container allows it, else a seccomp or platform egress policy) and add a Linux
  test that an engine cannot open a socket. Record in `docs/deployment.md` which of the two the
  deployment relies on. Until then, correct the two documents so they stop claiming it.

### H2. ClamAV is installed but never runs, so uploads are stored unscanned in production

- Where: `Dockerfile:105-120` installs `clamav` (clamscan, freshclam; clamd is in
  `clamav-daemon`), `routes/uploads.go:121-124` enables scanning only when `CLAMAV_ADDR` is set,
  `.env.example:76-77` leaves it empty, `docs/deployment.md` does not mention a clamd service.
- Problem: out of the box the production image scans nothing, logs one warning at boot
  (`internal/ingest/ingest.go:88`) and carries the package weight for no use. `AGENTS.md` says
  "secure by default, fail closed".
- Proposal: either a documented clamd sidecar in the compose file (M1) with `CLAMAV_ADDR` set, and
  `/health/deep` reporting it, or drop `clamav` from the image. Optionally refuse to boot in
  `APP_ENV=production` with no scanner unless `CLAMAV_DISABLED=true` is set on purpose.

## Medium

### M1. No compose file: local use needs Postgres, the engines and the worker by hand

- Where: repository root (no `docker-compose.yml`), `ROADMAP.md` 4.b.
- Problem: the project needs PostgreSQL, ffmpeg, libvips, qpdf, LibreOffice and others. On
  Windows and macOS `sandbox_other.go:15` returns an error, so conversions cannot run outside the
  container at all, and the tests that need engines or Postgres skip (`tests/migrations_test.go:20`,
  4 in `internal/engine/engine_test.go`). A newcomer cannot see the suite fully green.
- Proposal: `compose.yaml` with `app`, `worker` (`QUEUE_IN_SERVE=false`), `postgres:18.1-alpine`
  (the CI pin) and clamd; a `make`/`bun` script that runs `go test -race ./...` inside it. Pin every
  image tag, no `latest`.

### M2. An upload dies five minutes after it finishes

- Where: `app/services/conversions.go:151` (`defaultResultTTLMinutes = 5`) and `:358` feed one TTL to
  the file store; `internal/files/files.go:170` stamps every file, inputs included, with it.
- Problem: the interface lets you upload, then pick options. A 500 MB upload over a slow link, or a
  pause to choose a format, and `submit` answers "That upload does not exist"
  (`app/controllers/apiv1/conversions.go:218`). The tus upload is kept 24 hours, but the stored
  input is not. Daily use of a batch of files fails.
- Proposal: a separate `UPLOAD_TTL_MINUTES` for `role=input` (default 60), keep 5 for results;
  `Unattached` and the sweep already key on `expires_at`.

### M3. `/health/deep` is anonymous, unthrottled and fingerprints the deployment

- Where: `routes/web.go:118` (no middleware), `app/controllers/health.go:103` (probes),
  `:193` (writes, reads and deletes an object per call), `:243` (exact engine versions in the body).
- Problem: anyone can make the server do a database query and a storage round trip on every
  request, and read the engine versions, which is the list an attacker matches against CVEs. The
  comment says "for an operator" but nothing enforces it.
- Proposal: require `METRICS_TOKEN`-style bearer auth (same mechanism as `/metrics`) or a per-IP
  limiter, and return versions only to the authenticated caller. `/health` stays open.

### M4. The daily budget can be overspent by concurrent work

- Where: `app/controllers/apiv1/conversions.go:267` and `internal/jobs/pipeline.go:341` check;
  `internal/jobs/pipeline.go:573` (`Spend`) records only when a conversion ends.
- Problem: check-then-spend. With `QUEUE_CONCURRENCY` workers and many queued jobs, every job passes
  the check before any has spent; the budget is exceeded by up to concurrency times the longest job.
  One slow video can overshoot a daily limit by the length of the video.
- Proposal: reserve an estimate at start (`Reserve` upserts the row) and settle at the end, or
  accept and document the bound. A test with N concurrent submissions near the limit.

### M5. No cap on stored bytes per account

- Where: `routes/uploads.go:68` limits only upload creation (30 per minute per token);
  `internal/files/files.go:342` (`Unattached`) is capped at 20 for display, not for storage.
- Problem: 30 uploads per minute of up to `MAX_UPLOAD_SIZE_MB=500` each, kept until expiry, is up to
  15 GB per minute per account on a small container disk; with M2 fixed it gets worse. The 24-hour
  tus expiry also holds partial files.
- Proposal: refuse a new upload when the account's live unattached plus output bytes exceed a
  `MAX_STORED_MB_PER_USER`; report it in `/api/v1/usage`.

### M6. The security-critical upload path has no tests

- Where: `internal/ingest/` (size, magic-byte identification, scanner failure handling; "no test
  files"), `internal/httpx/` (API key header middleware used by every API route), `routes/`
  (middleware wiring, rate limits, auth guards), `bootstrap/`.
- Problem: the cross-cutting gates in `tests/` exercise it indirectly, but a regression in
  "a scanner that cannot be reached is a refusal" (`ingest.go:176-196`) or in the accepted-type
  list would not be caught by name. The fail-closed claims in the code comments are unproven.
- Proposal: table tests for `Accept` with fake `upload.Scanner` (infected, unreachable, ok), a
  mismatching extension, an oversize `Length`; a test per `httpx` middleware; one route-tree test
  asserting every non-public route carries an auth guard.

### M7. Engine tests skip silently where the binaries are absent

- Where: 4 skips in `internal/engine/engine_test.go`, 5 in `internal/downloader/network_test.go`,
  3 in `tests/image_compress_test.go`, plus bench files.
- Problem: on a laptop `go test ./...` prints `ok` while skipping the engine coverage; there is no
  one-line way to say "I want the engines or fail".
- Proposal: an env flag (`REQUIRE_ENGINES=1`) that turns those skips into failures, set in CI and
  in the compose test target (M1).

### M8. Vukem is two minors behind the framework

- Where: `go.mod:6` pins `v0.41.0`; the latest tag is `v0.43.0`, and `ROADMAP.md` 4.0 asks for
  `v0.44.0`, which is not released yet. The branch name says v0.41.0.
- Proposal: bump to the newest tag at merge time, regenerate the clients, and read
  `docs/vukem-audit.md`'s rule (verify against the pinned module, not this repo) for any
  `workaround(vukem)` marker.

## Low

### L1. `isNoRows` compares an error message

- Where: `internal/quota/quota.go:236`. The comment says `sql.ErrNoRows` is "not reachable without
  importing"; it is `database/sql`, a standard package. A wrapped or reworded error would turn
  "no usage today" into a hard failure of every conversion.
- Proposal: `errors.Is(err, sql.ErrNoRows)`, plus a test with a wrapped error.

### L2. The production image has no `HEALTHCHECK`

- Where: `Dockerfile:131-136`. `/health` exists (`routes/web.go:117`) but a plain `docker run` or
  compose has no probe.
- Proposal: `HEALTHCHECK` calling the binary or curl-free probe against `/health`.

### L3. One apt line is glued with tabs

- Where: `Dockerfile:105` joins ten packages with tab characters instead of line continuations,
  where the other lines use a trailing backslash. It works, but it is unreadable, and a diff on one pin rewrites the
  whole line. This is the line the bump PRs for Debian pins touch.
- Proposal: one package per line, each ending in a backslash.

### L4. `/lookup/*` has no server-side cache

- Where: `app/controllers/lookup.go:59-95`. Each call goes to ViaCEP or BrasilAPI;
  `Cache-Control: private, max-age=3600` helps one browser only. Per-IP 30 per minute
  (`routes/web.go:158`) protects us but not the free providers.
- Proposal: a small TTL cache (the app cache store) keyed by CEP or CNPJ.

### L5. The login throttle key swallows a malformed JSON body

- Where: `app/controllers/account/account.go:76` (`_ = json.Unmarshal(body, &in)`). A body that is
  not JSON yields an empty email, so the throttle key falls back to the generic bucket. Not
  exploitable on its own (the IP limiter and per-account limiter remain), but the ignored error is
  the pattern `AGENTS.md` forbids.
- Proposal: on error, key by IP only and say so in a comment; test it.

### L6. `_ = result` in the archive tool

- Where: `app/tools/archive.go:332`. A value computed and discarded to silence the compiler.
- Proposal: drop the variable (`_, err :=`) or report the figures in the `Outcome`.

### L7. The frontend has no linter and thin tests

- Where: `package.json` (no ESLint or Biome), 68 files under `resources/js`, 8 test files.
  The plans (`plans/NEXT.md` N3) already note it.
- Proposal: Biome (needs the owner's approval for the dependency); tests for the upload and
  conversion-status hooks, which are where the browser talks to tus and the API.

### L8. Stale ROADMAP gates

- Where: `ROADMAP.md:41-54` lists the global gates unchecked although most are met (CI green,
  actions pinned, git-cliff changelog). `plans/NEXT.md` N4 says the same.
- Proposal: tick what is proven, with the command, as the rule requires.

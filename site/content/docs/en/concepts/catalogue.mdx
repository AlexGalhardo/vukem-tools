The catalogue has 54 tools. Each has a name, and the name is the same everywhere: the page `/tools/<name>`, the API route `POST /api/v1/tools/<name>`, and the MCP tool. `vukem-tools tools` prints the list as JSON.

## Tools that run on the server (37)

They go through the conversion pipeline: upload, convert in an engine, download. You can run them from the web app, the API, the CLI and MCP. Each row links to the arguments and options of its tools.

## Tools that run in the browser (17)

They run in the page. Nothing is uploaded to a conversion engine, and they have no API route, no CLI command and no MCP call. In the catalogue they are marked `Client`.

| Group | Tools |
| --- | --- |
| Developer tools (9) | `base64`, `data-convert`, `diff`, `hash`, `json-format`, `json-schema`, `jwt-decode`, `password`, `uuid` |
| LLM and agents (4) | `chat-template`, `llm-clean`, `llm-cost`, `token-count` |
| Brazil (4) | `cep-lookup`, `cnpj-lookup`, `cpf-cnpj`, `fake-person` |

`cep-lookup` and `cnpj-lookup` ask a public service (ViaCEP and BrasilAPI) for the data they show. The rest compute in the page.

## What a server offers

A server only offers a tool whose engine it has. Engines such as qpdf, ffmpeg, libvips and LibreOffice run as separate processes, each with a time limit. When one is missing, the server logs it and hides the tools that need it. `GET /api/v1/tools` lists what a server offers and `GET /api/v1/capabilities` says which engines it found and what its limits are. See [Endpoints](/docs/api/endpoints).

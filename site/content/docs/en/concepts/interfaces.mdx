---
title: "One catalogue, four doors"
description: "The web app, the desktop app, the HTTP API, the CLI and MCP all call the same tools."
---

There is one set of tools and several ways in. Pick the one that fits what you are doing.

| Door | How you open a tool | Good for |
| --- | --- | --- |
| Web app | `/tools/<name>` after you sign in | Doing it by hand |
| Desktop app | The window opens the same web app | Using it on one computer with no setup |
| HTTP API | `POST /api/v1/tools/<name>` with an API key | Scripts and programs |
| CLI | `vukem-tools <area> <tool>` | The terminal and shell scripts |
| MCP | `vukem-tools mcp`, then `tools/call` | AI agents |

The CLI and MCP are not a second implementation. Both are clients of the HTTP API: they upload your file, submit the conversion, wait, and download the result. So a server, a key and the key's abilities are the same behind every door except the browser tools, which run in the page.

## Servers and ports

| Program | Listens on | Role |
| --- | --- | --- |
| The web app (`cmd/app`, the Docker image) | Port 3000 by default | The server: web interface and `/api/v1`. |
| The desktop app | A free loopback port it picks each time | The same server, started for you in local mode. |
| `vukem-tools serve` | `127.0.0.1:8787` by default | A local HTTP form of the MCP server. It is a client of the web app, not a server of tools. |

`vukem-tools` and `vukem-tools mcp` open no port.

---
title: "Releases"
description: "How a version tag becomes a GitHub release, an image, and three desktop files."
---

Versions are SemVer below 1.0. The changelog is generated by git-cliff from Conventional Commits. Do not edit a released section by hand.

A release commit changes `CHANGELOG.md` and `package.json`, with the message `chore(release): vX.Y.Z`. The annotated tag is pushed on its own. The tag points at a commit that already contains the desktop jobs.

The release workflow runs the tests, pushes the signed image, builds the three desktop files, and uploads them. The file names include the version: `vukem-tools-0-7-0.exe` and the matching AppImage and dmg. The workflow reads the notes from the changelog section. An empty section fails the job.

Do not move a tag that was already pushed. If the workflow fails, fix the cause and run it again on the same tag.

title: "Protocol"
description: "The JSON-RPC methods of vukem-tools mcp, what a call returns, the error codes, and the local HTTP form."
---

`vukem-tools mcp` reads one JSON-RPC 2.0 message per line on standard input and writes one per line on standard output. Anything it has to say about itself goes to standard error. A batch (a JSON array) is not supported and is answered with `-32600`.

## Methods

| Method | Result |
| --- | --- |
| `initialize` | Echoes the protocol version the client asked for (`2025-06-18` when it names none), the capability `tools`, and `serverInfo` with the name `vukem-tools` and the version. |
| `ping` | An empty object. |
| `tools/list` | Every tool, under `result.tools`. See [Tools](/docs/mcp/tools). |
| `tools/call` | Runs one tool. |
| `notifications/cancelled` | Cancels the running call whose id is in `params.requestId`. |
| Any other `notifications/*` | Ignored. No answer. |

Any other method is answered with the JSON-RPC error `-32601`. Malformed JSON is `-32700`. A `tools/call` with an unknown tool name, or with params that are not an object with a name, is `-32602`.

Up to four `tools/call` requests run at once on one connection. The rest wait their turn, and `ping` is still answered while a long conversion runs.

## tools/list

Each entry has `name`, `title`, `description`, an `inputSchema` (JSON Schema) and `_meta` with the `kind` (`pipeline` or `browser`), the `group` and, for a pipeline tool, the CLI `area` and `command`. The schema is closed: an argument it does not name is refused.

A browser tool has an empty schema and a description that says it runs in the browser.

## tools/call

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pdf-crop","arguments":{"input":"in.pdf","output":"out.pdf","options":{"left":36,"bottom":36,"right":36,"top":36}}}}
```

The arguments are `input` (one file) or `inputs` (several), `output`, `options` and `idempotency_key`. Each tool's section in [Tools](/docs/mcp/tools) says which apply.

A call that works returns `isError: false`, the result as text in `content`, and the same result as an object in `structuredContent`:

```json
{
  "tool": "pdf-crop",
  "conversion_id": "01M82GGTYZJGR4M7382YEREYXG",
  "status": "finished",
  "outputs": [{ "path": "out.pdf", "name": "in.pdf", "mime": "application/pdf", "size_bytes": 1234 }],
  "bytes_in": 1500,
  "bytes_out": 1234,
  "note": "",
  "expires_at": "2026-11-22T20:57:47Z"
}
```

`outputs` has one entry per file written. `note` is what the conversion says about itself, when it has something to say. The fields `bytes_in`, `bytes_out`, `note` and `expires_at` are left out when empty.

## Tool errors

A failed tool is not a protocol error. The call returns `isError: true`, and the model sees the error:

```json
{"error":{"code":"missing_ability","message":"The API key may not run this tool: ...","retry":false}}
```

`code` is stable, so an agent can branch on it. `message` is a sentence to act on. `retry` is `true` when sending the same call again could work. A failure after a conversion started adds `conversion_id` and, for a failed conversion, `conversion_type`, the [conversion error code](/docs/api/errors#conversion-error-codes).

| Code | Meaning |
| --- | --- |
| `invalid_input` | An argument is missing, unknown or out of range, or a file is not readable or is empty. Checked before anything is uploaded. |
| `missing_key` | `VUKEM_TOOLS_API_KEY` is not set. |
| `unauthorized` | The server refused the key. |
| `missing_ability` | The key lacks the tool's ability. |
| `file_too_large` | The file is past the server's upload limit. |
| `not_found` | The server has no such resource. |
| `upload_failed` | The upload did not complete. |
| `result_expired` | The result was deleted before it was downloaded. |
| `rate_limited` | A rate limit. The server waited and retried first. |
| `conversion_failed` | The conversion ended in `error`. See `conversion_type`. |
| `conversion_cancelled` | The conversion was cancelled. |
| `timeout` | The conversion did not end in time. The default wait is 10 minutes. |
| `server_error` | The server answered with an error, or something unexpected happened. |
| `network_error` | The server could not be reached. |
| `io_error` | A file could not be read or written locally. |
| `browser_only` | The tool runs in the browser and has no call. |
| `unknown_tool` | No tool has that name. |

## Local HTTP

`vukem-tools serve` offers the same server over HTTP, for a program that cannot spawn a process. It listens on `127.0.0.1:8787` unless you pass `--addr host:port`.

| Route | What it does |
| --- | --- |
| `GET /tools` | The same list as `tools/list`, as `{"tools": [...]}`. |
| `POST /mcp` | One JSON-RPC message in, one out. A notification gets `202`. |

```bash
vukem-tools serve --addr 127.0.0.1:8787
curl -sS http://127.0.0.1:8787/tools
```

It exists to be used from the same machine, and it enforces that. It refuses to listen on any address that is not loopback (`127.0.0.1`, `::1` or `localhost`), answers only requests whose `Host` is loopback, refuses any request with an `Origin` header so a web page cannot use it, and wants `Content-Type: application/json` on `POST /mcp`. It is a different surface from the web app, which listens on port 3000.

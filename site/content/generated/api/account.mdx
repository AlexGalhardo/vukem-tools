## POST /api/v1/device-links/token

**Collect the key of an approved link.**

Poll every `interval` seconds. status is pending until the person decides, then approved with the key (shown once and made at that moment), denied, or expired. A link that never existed reads as expired.

| Property | Value |
| --- | --- |
| Auth | None |
| Ability | None. The route is public. |

**Request body** (`application/json`)

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `device_code` | string | yes | The device_code from the call that started the link. min length 1; max length 128 |

**Example**

```bash
curl -sS -X POST "$VUKEM_TOOLS_URL/api/v1/device-links/token" \
  -H "Content-Type: application/json" \
  -d '{
  "device_code": "kV3x0Zp8mQ1sT9nL2aR7wYc4HbU6eGdJ5oFiNtX-AqE"
}'
```

**Responses**

| Status | Meaning | Body |
| --- | --- | --- |
| 200 | OK | `LinkToken` |
| 422 | The input was refused; `errors` names each field | [Problem](/docs/api/errors) |
| Other | An error, as a problem document | [Problem](/docs/api/errors) |

Example of a success body:


## POST /api/v1/device-links

**Start linking a program to an account.**

For a program that cannot show a login form, such as a chat bot. Returns a secret device_code to poll with and a short user_code to show the person, who opens verification_url in a browser, checks the code and approves. What the key may do is fixed by the client kind, not asked for. Rate limited per IP.

| Property | Value |
| --- | --- |
| Auth | None |
| Ability | None. The route is public. |

**Request body** (`application/json`)

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `client` | string | yes | The kind of program asking. It decides what the key may do: the server fixes the abilities, the program cannot choose them. one of `telegram`; min length 1 |
| `device_name` | string | no | A label for the key in the account's key list, such as the Telegram name of the person. Optional. max length 64 |

**Example**

```bash
curl -sS -X POST "$VUKEM_TOOLS_URL/api/v1/device-links" \
  -H "Content-Type: application/json" \
  -d '{
  "client": "telegram",
  "device_name": "Telegram: ana"
}'
```

**Responses**

| Status | Meaning | Body |
| --- | --- | --- |
| 201 | Created | `LinkStarted` |
| 422 | The input was refused; `errors` names each field | [Problem](/docs/api/errors) |
| Other | An error, as a problem document | [Problem](/docs/api/errors) |

Example of a success body:

```json
{
  "device_code": "kV3x0Zp8mQ1sT9nL2aR7wYc4HbU6eGdJ5oFiNtX-AqE",
  "expires_in": 600,
  "interval": 3,
  "user_code": "BCDF-2346",
  "verification_url": "http://localhost:3000/account/link?code=BCDF-2346"
}
```

## POST /api/v1/tokens

**Issue an API key.**

Exchanges email and password for an API key limited to the abilities asked for. The secret is returned once and never stored: only its SHA-256 hash is.

| Property | Value |
| --- | --- |
| Auth | None |
| Ability | None. The route is public. |

**Request body** (`application/json`)

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `abilities` | array of string | yes | What the key may do; GET /api/v1/abilities lists the accepted values. at least 1 items; at most 16 items |
| `code` | string | no | A two-factor code, for accounts with two-factor authentication. max length 16 |
| `device_name` | string | yes | A label for this key, shown when listing keys. min length 1; max length 100 |
| `email` | string | yes | The account's email address. min length 1 |
| `password` | string | yes | The account's password. min length 1 |
| `recovery_code` | string | no | A two-factor recovery code, instead of code. max length 32 |

**Example**

```bash
curl -sS -X POST "$VUKEM_TOOLS_URL/api/v1/tokens" \
  -H "Content-Type: application/json" \
  -d '{
  "abilities": [
    "image:convert",
    "pdf:compress"
  ],
  "device_name": "cli",
  "email": "you@example.com",
  "password": "your-account-password"
}'
```

**Responses**

| Status | Meaning | Body |
| --- | --- | --- |
| 201 | Created | `TokenIssued` |
| 422 | The input was refused; `errors` names each field | [Problem](/docs/api/errors) |

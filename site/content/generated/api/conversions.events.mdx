## Authentication

Send your API key as `Authorization: Bearer <key>`. The `X-API-Key` header works too, and `Authorization` wins when both are present. Any valid key works: no ability is needed.

## Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | yes | The conversion's id, as returned when it was submitted. min length 1 |

## Responses

### 200 OK

Content type `text/event-stream`. The first event is always the current state, so a client that connects after the work is done still learns the outcome. Then come the events it missed after `Last-Event-ID`, then live ones. When the conversion has ended the server closes the stream. A conversion that is not yours is a `404`.

Every event is named `progress`. Its `data` is one JSON object:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | integer | yes | The event's place in the trail. Send the last one you saw as `Last-Event-ID` to resume. |
| `conversion_id` | string | yes | The conversion. |
| `status` | string | yes | `pending`, `running`, `finished`, `error` or `cancelled`. |
| `progress` | integer | yes | 0 to 100. |
| `phase` | string | yes | What it is doing now. |
| `message` | string | yes | Client-safe text. Never a path or an engine argument. |
| `error_type` | string | no | Only on a failure: a code from [the conversion error codes](/docs/api/overview#conversion-error-codes). |
| `at` | string | yes | When the event happened, as a date-time. |

### 401 Unauthorized

Content type `application/problem+json`. Schema: [`Problem`](/docs/api/schemas#problem).

### 404 Not Found

Content type `application/problem+json`. No such conversion, or it is not yours. Schema: [`Problem`](/docs/api/schemas#problem).

## Authentication

Send your API key as `Authorization: Bearer <key>`. The `X-API-Key` header works too, and `Authorization` wins when both are present. Any valid key works: no ability is needed.

## Query parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `limit` | `integer` | no | How many to return, 1 to 100. Default 20. min 0; max 100 |

## Responses

### 200 OK

Content type `application/json`. Schema: [`ConversionList`](/docs/api/schemas#conversionlist).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `data` | array of [`ConversionView`](/docs/api/schemas#conversionview) | - | The caller's conversions, newest first |

### 401 Unauthorized

Content type `application/problem+json`. Error (RFC 9457 problem details). Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

### 422 Unprocessable Content

Content type `application/problem+json`. Validation failed; errors maps each field to its messages and issues lists each problem with its code, key and params. Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

### Any other status

Content type `application/problem+json`. Error (RFC 9457 problem details). Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

List your uploads, then follow, cancel and collect a conversion. Every example reads the server from `VUKEM_TOOLS_URL` and the key from `VUKEM_TOOLS_API_KEY`; see [the overview](/docs/api/overview) for how to set them.

## The conversion object

Every route that submits a conversion answers with a `ConversionView`, and so do the routes that show and cancel one.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `bytes_in` | integer | no | Size of the input in bytes. |
| `bytes_out` | integer | no | Size of the result in bytes, 0 until it finishes. |
| `created_at` | string | no | When it was submitted. |
| `error_message` | string | no | What to tell the user, empty unless it failed. |
| `error_type` | string | no | A code from the error taxonomy, empty unless it failed. |
| `expires_at` | string | no | When the result stops being downloadable. |
| `finished_at` | string or null | no | When it ended, or null. |
| `id` | string | no | The conversion id, used to poll it, stream it or cancel it. |
| `note` | string | no | What the conversion did, in its own words. Empty when the file says it all. |
| `phase` | string | no | What it is doing now, empty once it has ended. |
| `progress` | integer | no | Percentage from 0 to 100. |
| `started_at` | string or null | no | When a worker picked it up, or null. |
| `status` | string | no | One of pending, running, finished, error, cancelled. |
| `tool` | string | no | Which conversion produced it. |

`status` moves from `pending` to `running` and ends as `finished`, `error` or `cancelled`. An `error_type` is one of [the conversion error codes](/docs/api/errors#conversion-error-codes).

```json
{
  "bytes_in": 18452,
  "bytes_out": 0,
  "created_at": "2026-02-03T10:00:00Z",
  "error_message": "",
  "error_type": "",
  "expires_at": "2026-02-03T11:00:02Z",
  "finished_at": null,
  "id": "01JQ8Z5X0K7M3N9P2R4T6V8W0Y",
  "phase": "tracing",
  "progress": 60,
  "started_at": "2026-02-03T10:00:02Z",
  "status": "running",
  "tool": "pixels-to-svg"
}
```


## GET /api/v1/conversions/\{id\}/result

**Get signed links to a conversion's result.**

Signed, expiring links to the files a finished conversion produced. A link is signed when you ask for it, so it is never older than your request.

| Property | Value |
| --- | --- |
| Auth | API key (`Authorization: Bearer` or `X-API-Key`) |
| Ability | Any valid key. No ability is needed. |

**Parameters**

| Name | In | Type | Required | Notes |
| --- | --- | --- | --- | --- |
| `id` | path | string | yes | The conversion's id, as returned when it was submitted. min length 1 |

**Example**

```bash
curl -sS "$VUKEM_TOOLS_URL/api/v1/conversions/$CONVERSION_ID/result" \
  -H "Authorization: Bearer $VUKEM_TOOLS_API_KEY"
```

## GET /api/v1/conversions/\{id\}/events

**Follow a conversion as it runs.**

A Server-Sent Events stream, so a client that can hold a connection open does not have to poll. It is in the route table but not in `/openapi.json`, because a stream has no response body a schema can describe.

| Property | Value |
| --- | --- |
| Auth | API key (`Authorization: Bearer` or `X-API-Key`) |
| Ability | Any valid key. No ability is needed. |

The first event is always the current state, so a client that connects after the work is done still learns the outcome. Then come the events it missed after `Last-Event-ID`, then live ones. When the conversion has ended the server closes the stream. A conversion that is not yours is a `404`.

Every event is named `progress`. Its `data` is one JSON object:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | integer | The event's place in the trail. Send the last one you saw as `Last-Event-ID` to resume. |
| `conversion_id` | string | The conversion. |
| `status` | string | `pending`, `running`, `finished`, `error` or `cancelled`. |
| `progress` | integer | 0 to 100. |
| `phase` | string | What it is doing now. |
| `message` | string | Client-safe text. Never a path or an engine argument. |
| `error_type` | string | Only on a failure: a code from [the error taxonomy](/docs/api/errors#conversion-error-codes). |
| `at` | string | When the event happened, as a date-time. |

**Example**

```bash
curl -sS -N "$VUKEM_TOOLS_URL/api/v1/conversions/$CONVERSION_ID/events" \
  -H "Authorization: Bearer $VUKEM_TOOLS_API_KEY"
```

```text
event: progress
data: {"id":0,"conversion_id":"01M82GGTYZJGR4M7382YEREYXG","status":"running","progress":0,"phase":"","message":"","at":"2026-11-22T20:52:49.0117598Z"}
```

**Responses**

| Status | Meaning | Body |
| --- | --- | --- |
| 200 | The stream | `text/event-stream` |
| 401 | No key, or a key that is not valid | [Problem](/docs/api/errors) |
| 404 | No such conversion, or it is not yours | [Problem](/docs/api/errors) |

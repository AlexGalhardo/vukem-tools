## Authentication

No key is needed: the codes in the exchange are the credential. This route is limited per address. See [Authentication](/docs/api/overview#authentication).

## Request body

Content type `application/json`.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `client` | `string` | yes | The kind of program asking. It decides what the key may do: the server fixes the abilities, the program cannot choose them. one of `telegram`; min length 1 |
| `device_name` | `string` | no | A label for the key in the account's key list, such as the Telegram name of the person. Optional. max length 64 |

## Responses

### 201 Created

Content type `application/json`. Schema: [`LinkStarted`](/docs/api/schemas#linkstarted).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `device_code` | `string` | - | Secret to poll with. Never show it to the person |
| `expires_in` | `integer` | - | Seconds until the link can no longer be approved |
| `interval` | `integer` | - | Seconds to wait between polls |
| `user_code` | `string` | - | The short code to show the person, formatted XXXX-XXXX |
| `verification_url` | `string` | - | Where the person approves. It already contains the user code |

### 422 Unprocessable Content

Content type `application/problem+json`. Validation failed; errors maps each field to its messages and issues lists each problem with its code, key and params. Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

### Any other status

Content type `application/problem+json`. Error (RFC 9457 problem details). Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

## Authentication

No key is needed: the codes in the exchange are the credential. This route is limited per address. See [Authentication](/docs/api/overview#authentication).

## Request body

Content type `application/json`.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `device_code` | `string` | yes | The device_code from the call that started the link. min length 1; max length 128 |

## Responses

### 200 OK

Content type `application/json`. Schema: [`LinkToken`](/docs/api/schemas#linktoken).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `abilities` | array of `string` | - | What the key may do. Only when approved |
| `expires_at` | `string (date-time)` or `null` | - | When the key stops working. Only when approved |
| `id` | `string` | - | The key id, used to revoke it. Only when approved |
| `status` | `string` | - | Pending, approved, denied or expired. A link that never existed reads as expired |
| `token` | `string` | - | The secret key, shown once. Only when approved |
| `type` | `string` | - | The authorization scheme, always Bearer. Only when approved |

### 422 Unprocessable Content

Content type `application/problem+json`. Validation failed; errors maps each field to its messages and issues lists each problem with its code, key and params. Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

### Any other status

Content type `application/problem+json`. Error (RFC 9457 problem details). Schema: [`Problem`](/docs/api/schemas#problem).

The error follows RFC 9457. See [Errors](/docs/api/overview#errors).

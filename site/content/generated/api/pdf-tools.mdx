## POST /api/v1/tools/excel-to-pdf

**Convert a spreadsheet to PDF.**

Converted with LibreOffice from the document's own page setup. A font the server does not have is replaced by a similar one, so line breaks can differ from the original application, and macros never run. Linked images that need the network are left out. Each sheet is paginated by its own print settings.

## POST /api/v1/tools/pdf-forms

**List, fill or flatten a PDF form.**

The list action returns every field as JSON: its full name, type (text, checkbox, radio, choice), current value, options and whether it is read-only. The fill action sets the values you give, by field name; a checkbox takes true or false, and a radio group or a choice takes one of its listed options. A field that does not exist, is read-only, or is given a value it cannot hold is refused rather than skipped. The flatten action, or flatten on a fill, turns the form into plain page content. Scripts in the form do not run, so calculated fields are not recalculated.

## POST /api/v1/tools/pdf-sign

**Sign a PDF with your own certificate.**

Exactly two uploads: the PDF and a .p12 (or .pfx) bundle holding your certificate and private key, with the bundle's password in the options. The signature is an invisible, detached CMS signature (adbe.pkcs7.detached) with SHA-256, RSA or ECDSA, and any PDF reader can verify it. The key is used for this one signature and is not kept: the bundle is deleted with the other uploads when they expire. A self-signed certificate proves the document has not changed since signing, but a reader will not vouch for who signed it until it trusts that certificate; this is not a qualified electronic signature. An expired certificate, an encrypted document, and a document that is already signed are refused, because signing again would invalidate the first signature.

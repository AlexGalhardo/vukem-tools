These 5 tools run on the server. Over MCP each is a `tools/call` with the arguments below; on the command line each is the `vukem-tools` command shown. Every tool reads its files from paths on your machine and writes the result to `output`.

## image-compress

**Compress an image.** Makes an image smaller without a visible difference, and reports exactly how much was saved.

The format never changes; image-convert is what changes a format. Each mode runs every encoder setting worth trying and keeps the smallest file, so a lossy compression can legitimately come back lossless when that was smaller. A file this encoder cannot beat is returned unchanged with the fact stated, rather than re-encoded into something larger. PNG and GIF compress losslessly by default, JPEG and WebP lossily; lossless is refused for JPEG, because libvips has no lossless JPEG re-encode and jpegtran is not in this image. Metadata is always removed.

| Property | Value |
| --- | --- |
| Ability | `image:compress` |
| CLI | `vukem-tools image compress` |
| API route | `POST /api/v1/tools/image-compress` |

**Arguments**

| Argument | Type | Required | Notes |
| --- | --- | --- | --- |
| `input` | string | yes | Path of the file to read. |
| `output` | string | yes | Where to write the result: a file path, or a directory for a tool that yields several files. |
| `options` | object | no | How hard to compress. Every field is optional. |
| `idempotency_key` | string | no | Repeat a call safely: the same key returns the same conversion. |

**Options**

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `options.effort` | integer | no | 1 to 10, meaning depends on the format. 0 uses the highest the encoder supports. min 0; max 10 |
| `options.mode` | string | no | Lossless or lossy. Empty picks by format: lossless for PNG and GIF, lossy for JPEG and WebP. max length 16 |
| `options.quality` | integer | no | 1 to 100, for a lossy compression. 0 uses the format's default. min 0; max 100 |

**Example**

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"image-compress","arguments":{"input":"in.file","output":"out.file"}}}
```

## image-convert

**Convert an image.** Between PNG, JPEG, WebP, AVIF and more, with control over quality and whether transparency is kept.

One libvips pass does all of it: a resize is a re-encode with a target size, and the orientation and colour handling happen on the same pass. EXIF is removed unless you ask for it, because a photograph's EXIF often carries GPS coordinates and a device serial number.

| --- | --- |
| Ability | `image:convert` |
| CLI | `vukem-tools image convert` |
| API route | `POST /api/v1/tools/image-convert` |

**Arguments**

| --- | --- | --- | --- |

**Options**

| Field | Type | Required | Notes |

| `options.crop_height` | integer | no | Crop height. 0 means no crop. min 0; max 20000 |
| `options.crop_left` | integer | no | Crop origin from the left, in source pixels. min 0; max 20000 |
| `options.crop_top` | integer | no | Crop origin from the top, in source pixels. min 0; max 20000 |
| `options.crop_width` | integer | no | Crop width. 0 means no crop. min 0; max 20000 |
| `options.effort` | integer | no | 0 to 10, meaning depends on the format. 0 uses the default. min 0; max 10 |

## pixels-to-svg

**Pixel art to SVG.** Traces pixel art into clean vector shapes, one path per colour region, with no blurring or smoothing.

Traces an uploaded image into SVG. The upload and the conversion are bound in one transaction, so a conversion always has its input. Send an idempotency_key to make a retry safe.

| Property | Value |

| Ability | `pixels:svg` |

## sprite-build

**Build a sprite sheet.** Packs a ZIP of frames into one sheet, with the atlas that describes it.

Takes a ZIP of frames. The grid layout gives every frame an identical cell and is the default, because it is what Godot 4 and Unity import with no metadata file at all; compact packs frames of differing sizes more tightly. Frames that do not fit are refused with the count that fitted and the size that would be needed, never silently dropped. The packer never rotates a frame.

| Property | Value |
| --- | --- |
| Ability | `sprite:sheet` |
| CLI | `vukem-tools sprite build` |
| API route | `POST /api/v1/tools/sprite-build` |

**Arguments**

| Argument | Type | Required | Notes |
| --- | --- | --- | --- |
| `input` | string | yes | Path of the file to read. |
| `output` | string | yes | Where to write the result: a file path, or a directory for a tool that yields several files. |
| `options` | object | no | How to pack the frames, and which metadata to write. |
| `idempotency_key` | string | no | Repeat a call safely: the same key returns the same conversion. |

**Options**

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `options.aseprite` | boolean | no | Add Aseprite's per-frame duration and frameTags to the JSON formats. |
| `options.extrude` | integer | no | Repeat each frame's edge pixels into the padding, which is the fix for the dark halo transparent padding leaves. min 0; max 8 |
| `options.frame_ms` | integer | no | Per-frame duration in milliseconds for the Aseprite extensions. 0 means 100. min 0; max 60000 |
| `options.layout` | string | no | Grid or compact. Default grid, which Godot 4 and Unity import with no metadata file. max length 8 |
| `options.margin` | integer | no | Transparent gutter at the sheet's edges. min 0; max 256 |

| `options.metadata` | array of string | no | Metadata formats to write, at most four. at most 4 items |
| `options.padding` | integer | no | Transparent gutter between two frames, which stops a neighbour's colour bleeding in. min 0; max 256 |
| `options.pot` | boolean | no | Round the sheet up to a power of two on both axes. |

**Example**

## sprite-split

**Split a sprite sheet.** Cuts a sheet into frames and writes the atlas a game engine imports.

Grid mode cuts the sheet on a grid you describe and is exact; auto mode finds each frame's bounding box from the sheet's own content, which is the answer for a hand-drawn sheet. A fully opaque sheet with no background colour named is refused rather than guessed at. The result is one archive — the frames and the metadata together, so one download is self-contained — plus each metadata file on its own. Trimming is refused with the css format, which has nowhere to record the offset.

| --- | --- |
| Ability | `sprite:sheet` |

**Options**

| Field | Type | Required | Notes |
